# 5. Платежи и правила платформы

## 5.1. Telegram Stars

Для цифровых валют и цифрового контента внутри Telegram основной provider — Telegram Stars (`XTR`).

Полный flow:

1. backend создаёт invoice;
2. Telegram присылает `pre_checkout_query`;
3. Qinghe проверяет продукт, цену и доступность;
4. Qinghe отвечает Telegram в установленный срок;
5. Telegram присылает `successful_payment`;
6. только после `successful_payment` создаются начисления;
7. сохраняется `telegram_payment_charge_id` для поддержки и refund.

Нельзя начислять валюту после открытия invoice, нажатия кнопки или клиентского callback без серверного подтверждения Telegram.

## 5.2. Tribute

Технически можно предусмотреть адаптер `tribute`, но включать продажу цифровой валюты через него внутри Telegram следует только после отдельной проверки соответствия правилам Telegram и площадок.

Рекомендуемая конфигурация первой production-версии:

```text
PAYMENTS_STARS_ENABLED=true
PAYMENTS_TRIBUTE_CURRENCY_ENABLED=false
```

Существующие Tribute-сценарии подписки не должны автоматически считаться разрешением продавать через Tribute внутреннюю валюту.

Provider-адаптер сохраняется в архитектуре, чтобы позже включить его без переделки ledger:

```text
PaymentProvider
  createCheckout()
  verifyCallback()
  paymentReference()
  refund()
```

## 5.3. Возвраты

Refund не удаляет покупку и ledger. Создаются компенсирующие операции:

```text
platinum reversal: -N
reader coins reversal: -N
purchase.status = refunded
```

Если часть валюты уже потрачена, политика должна быть определена до запуска. Безопасный вариант:

- доступный баланс уменьшается до разрешённого значения;
- дефицит фиксируется как `currency_debt`;
- новые покупки блокируются до погашения;
- уже выданный цифровой контент отзывается только согласно опубликованным условиям возврата.

Автоматически создавать отрицательный пользовательский баланс без отдельной продуктовой политики нельзя.

## 5.4. Поддержка

В обоих приложениях должны быть:

- условия покупки;
- правила возврата;
- ссылка поддержки;
- идентификатор покупки, который пользователь может скопировать;
- команда бота `/paysupport`, если покупка проводится ботом.
