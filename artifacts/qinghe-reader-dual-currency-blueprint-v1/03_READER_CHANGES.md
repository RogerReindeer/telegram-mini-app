# 3. Изменения читалки

## 3.1. Backend

Добавить сервисы:

```text
app/services/coins.py
app/services/store.py
app/services/commerce_auth.py
app/routers/store.py
app/routers/internal_commerce.py
app/schemas_commerce.py
```

### Пользовательские endpoint

- `GET /api/store/wallet` — баланс Монеток;
- `GET /api/store/products` — доступные товары;
- `GET /api/store/purchases` — история покупок;
- `POST /api/store/purchase` — атомарная покупка товара;
- `POST /api/store/qinghe-checkout` — получить ссылку на Qinghe;
- `GET /api/store/entitlements` — действующие права.

### Внутренний endpoint

- `POST /api/internal/commerce/coin-grants` — начисление Монеток из Qinghe.

Этот endpoint не использует пользовательскую Telegram cookie. Он требует server-to-server подпись и принимает только allow-listed операции.

## 3.2. Кошелёк Монеток

- баланс хранится отдельно от Платины;
- начисление из Qinghe использует `purchase_id` как idempotency key;
- списание выполняется транзакционно;
- отрицательный баланс запрещён;
- ledger-записи не удаляются и не редактируются;
- корректировки оформляются отдельной компенсирующей записью.

## 3.3. Каталог читалки

Продукт содержит:

```text
product_code
product_type
title
coin_price
novel_id
chapter_id
subscription_role
duration_days
upgrade_from_role
is_active
metadata
```

Сервер обязан проверить, что указанный ресурс существует и доступен для продажи.

## 3.4. Покупка контента

Операция должна происходить в одной транзакции:

1. заблокировать кошелёк;
2. загрузить продукт с сервера;
3. проверить, не куплен ли он ранее;
4. проверить баланс;
5. списать Монетки;
6. записать покупку;
7. создать entitlement;
8. вернуть новый баланс и права.

Повторная отправка того же `client_action_id` возвращает прежний результат и не списывает Монетки повторно.

## 3.5. Интеграция с access.py

Перед существующим paywall добавить проверку commerce-entitlement:

```text
chapter_unlock для chapter_id
  OR novel_unlock для novel_id
  OR активная subscription с нужной ролью
  OR существующие правила бесплатного/подарочного доступа
```

Рекомендуемый приоритет:

1. скрытая книга или глава — отказ независимо от покупки;
2. постоянная покупка главы/книги;
3. активная подписка;
4. бесплатный доступ по дате;
5. существующие Telegram-группы и legacy-entitlements;
6. paywall.

## 3.6. UI читалки

Добавить:

- баланс Монеток в библиотеке и настройках;
- кнопку `Купить Монетки`;
- карточки покупки главы и книги;
- блок подписки и улучшения;
- подтверждение перед списанием;
- экран успешной покупки;
- восстановление состояния после возврата из Qinghe;
- понятное состояние `Начисление обрабатывается`;
- историю операций.

Paywall получает четыре CTA в зависимости от продукта:

- `Купить главу за N Монеток`;
- `Купить книгу за N Монеток`;
- `Оформить подписку`;
- `Улучшить подписку`.

Если Монеток недостаточно, основная кнопка меняется на `Купить Монетки в Qinghe`.

## 3.7. Read-only preview

Browser admin/reader-preview не должен:

- получать кошелёк реального пользователя;
- создавать checkout;
- покупать товары;
- записывать ledger;
- изменять entitlement.

Для preview endpoint магазина возвращает `read_only=true` и нулевой демонстрационный баланс.
