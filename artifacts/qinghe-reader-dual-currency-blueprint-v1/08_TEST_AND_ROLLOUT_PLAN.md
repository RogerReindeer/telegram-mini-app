# 8. Тестирование и запуск

## 8.1. Unit tests Qinghe

- повторный payment webhook не начисляет повторно;
- неверная цена invoice отклоняется;
- неизвестный product отклоняется;
- баланс Платины не становится отрицательным;
- purchase и outbox создаются атомарно;
- retry не создаёт новый event ID;
- refund создаёт reversal;
- checkout нельзя использовать другим Telegram user.

## 8.2. Unit tests читалки

- grant с корректной подписью начисляет Монетки;
- повтор event ID возвращает duplicate;
- одинаковый purchase с другим amount возвращает conflict;
- просроченная подпись отклоняется;
- повтор nonce отклоняется;
- preview не может покупать;
- покупка главы списывает один раз;
- недостаточный баланс не изменяет ledger;
- купленная глава открывается;
- покупка книги открывает главы книги, но не скрытый контент;
- подписка истекает по времени;
- upgrade не понижает роль.

## 8.3. Integration tests

1. Создать тестового пользователя.
2. Создать checkout на пакет 100.
3. Симулировать успешный Stars payment.
4. Проверить +100 Платины.
5. Проверить outbox.
6. Доставить +100 Монеток.
7. Повторить webhook и доставку.
8. Убедиться, что оба баланса остались 100.
9. Потратить 20 Платины.
10. Убедиться, что Монетки остались 100.
11. Купить главу за 30 Монеток.
12. Убедиться: Платина 80, Монетки 70.

## 8.4. Failure tests

- читалка отключена во время покупки;
- timeout после того, как читалка уже начислила Монетки;
- Qinghe перезапущен между payment и grant;
- две одновременные покупки одного пользователя;
- две одновременные покупки контента;
- повреждённая подпись;
- неверное системное время;
- Supabase временно недоступен;
- PostgreSQL Qinghe временно недоступен;
- refund после частичной траты валют.

## 8.5. Порядок релиза

### Этап 0 — решения

- утвердить цены Stars;
- утвердить правила refund;
- утвердить цены контента в Монетках;
- утвердить длительность подписки и upgrade;
- решить статус Tribute после compliance review.

### Этап 1 — базы и backend под flags

- сделать backup обеих БД;
- применить миграции на staging;
- развернуть backend с выключенными feature flags;
- проверить production-gate.

### Этап 2 — двойное начисление

- включить тестовые Stars;
- проверить пакеты 100/200/500/1000;
- проверить outbox и retry;
- включить `COMMERCE_ENABLED` для ограниченной группы.

### Этап 3 — магазин читалки

- добавить продукты глав и книг;
- включить покупку только для тестовой книги;
- проверить access и direct routes;
- добавить подписку;
- добавить upgrade отдельным релизом.

### Этап 4 — production

- включить алерты;
- опубликовать условия и поддержку;
- провести реальную минимальную покупку;
- сверить Stars payment, два ledger и entitlement;
- расширять rollout постепенно.

## 8.6. Rollback

- выключить `COMMERCE_ENABLED` и `STORE_ENABLED`;
- не удалять таблицы и ledger;
- остановить создание новых checkout;
- продолжить доставку уже оплаченных pending grants;
- исправлять ошибочные операции reversal-записями;
- не откатывать миграцию, пока есть реальные покупки.
